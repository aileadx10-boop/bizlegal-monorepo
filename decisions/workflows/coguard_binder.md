# CoGuard Court Binder Workflow

**WAT layer:** Workflow (this SOP)
**Agent:** None — fully deterministic
**Tools:** `/api/binder/generate` → `services/hetzner/coguard_binder.py` (ReportLab) → Supabase Storage → email

---

## Objective

Generate a professionally formatted PDF court binder from a subscriber's logged communications, with:
- Chain-of-custody certificate (SHA-256 verification, platform attestation)
- Incident index (flagged messages with hostility_score > 0.7)
- Full chronological message log with Bates numbers
- Attorney access invitation on the cover

---

## Trigger

Subscriber selects date range in `/dashboard/binders` and clicks "Generate Court Binder".

```
POST /api/binder/generate { date_from, date_to }
  → Auth check: subscriber owns this session
  → Verify plan allows binder generation
  → INSERT coguard_binders { subscriber_id, date_from, date_to, status='pending' }
  → Fire-and-forget POST to Hetzner coguard_binder.py (x-internal-secret)
    { binder_id, subscriber_id, date_from, date_to }
  → Return { binder_id } immediately (don't await Hetzner)
```

---

## Hetzner Binder Generator

`services/hetzner/coguard_binder.py` — FastAPI endpoint on port 8083

```python
# Sequence
1. UPDATE coguard_binders SET status='generating'
2. SELECT coguard_messages WHERE subscriber_id = ? AND received_at BETWEEN ? AND ?
   ORDER BY received_at ASC
3. Compute Bates start: SELECT MAX(bates_end) FROM coguard_binders WHERE subscriber_id = ?
   Bates start = MAX(bates_end) + 1 (or 1 if first binder)
4. ReportLab PDF generation:
   - Page 1: Chain-of-custody certificate
   - Page 2: Incident index (hostility_score > 0.7)
   - Pages 3+: Full message log with Bates numbers

5. Upload to Supabase Storage:
   bucket: coguard-binders (private, service-role only)
   path: {subscriber_id}/{binder_id}.pdf

6. Generate signed URL (24h expiry) from Supabase Storage
7. UPDATE coguard_binders SET status='ready', pdf_url=signed_url,
     message_count=N, bates_start=start, bates_end=end, completed_at=now()
8. Send email to subscriber: "Your court binder is ready"
   Includes: signed download URL (expires 24h), Bates range BL-XXXX-XXXXXXX to BL-XXXX-YYYYYYY
9. logEventAsync({ type: 'coguard.binder.generated', source: 'coguard' })
```

Subscriber:          [subscriber email]

Period Covered:      {date_from} to {date_to}
Messages Logged:     {N}
Bates Range:         {bates_start} to {bates_end}
Generated:           {timestamp UTC}
Platform:            CoGuard (coguard.bizlegal-ai.com)

INTEGRITY STATEMENT
Each message in this log was recorded with a SHA-256 cryptographic hash
at the time of receipt or sending. The hashes below verify the log has
not been altered since initial capture.

[Table: Bates | channel | received_at | sha256_hash]

https://coguard.bizlegal-ai.com/attorney/verify?code={access_code}

### Page 2 — Incident Index

Flagged messages with hostility_score > 0.7, sorted by score descending:
- Bates number | Date | Direction | Score | Flags | First 100 chars

### Pages 3+ — Full Message Log

Chronological, one entry per message:
```
┌──────────────────────────────────────────────────┐
│ Bates: BL-XXXXXXX-0000001        [OUTGOING]      │
│ Date:  2026-08-16 14:23 UTC                      │
│ From:  subscriber → ex@email.com                 │
│ SHA-256: abc123...                               │
├──────────────────────────────────────────────────┤
│ Hi, confirming pickup at 3pm Saturday at school. │
│                                                  │
│ [Sent via CoGuard • ref:#BL-XXXXXXX-0000001]     │
└──────────────────────────────────────────────────┘
```

---

## Bates Numbering Format

`BL-{subscriber_short}-{7-digit-zero-padded}`

- `subscriber_short` = first 8 chars of subscriber_id UUID (no dashes)
- Counter is per-subscriber, sequential across all binders
- Never resets — even if a binder is deleted, the range is reserved

## Systemd Unit

`/etc/systemd/system/coguard-binder.service`:
```
[Unit]
Description=CoGuard Court Binder Generator
After=network.target

[Service]
Type=simple
User=curator
WorkingDirectory=/opt/bizlegal/coguard
ExecStart=/opt/bizlegal/venv/bin/python -m uvicorn coguard_binder:app --port 8083
Restart=always
EnvironmentFile=/opt/bizlegal/.env

[Install]
WantedBy=multi-user.target
```

## Edge Cases

| Scenario | Handling |
|---|---|
| Zero messages in range | Return 400 "No messages found in selected range" |
| Hetzner down | `/api/binder/status/{id}` shows 'pending'; subscriber can re-trigger |
| Binder generation takes >60s | Async; subscriber polls `/api/binder/status/{id}` |
| Signed URL expires | Subscriber can click "Regenerate download link" (no PDF recreation, just new signed URL) |
| Very large binder (1000+ messages) | ReportLab handles up to ~5000 pages; chunk if needed |

`coguard_binders` row with `status='ready'`, non-null `pdf_url`, `bates_start`, `bates_end`. PDF downloads. Cover page shows chain-of-custody certificate with correct SHA-256 hashes. Attorney access link visible on cover.
