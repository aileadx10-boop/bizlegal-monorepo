# Gap-page visual enrichment

`scripts/generate-gap-visuals.mjs` adds visuals to the SEO **gap pages**
(`public.gap_pages`, Supabase project `ydghhcuuopqzgqcicubg`) that the forge
app renders at `/gap/[jurisdiction]/[slug]`:

- **Hero image** — a clean editorial infographic generated by OpenAI
  `gpt-image-1`, uploaded to the Supabase Storage bucket `gap-visuals`, with
  the public URL stored in `gap_pages.hero_image_url`.
- **Mermaid diagram** — a compliance decision/flow chart generated by the
  Anthropic API, stored in `gap_pages.diagram_mermaid` (+ `diagram_caption`).

The renderer shows the hero `<img>` near the top and renders the Mermaid
source client-side (lazy-loaded from a CDN) with a server-safe `<pre>`
fallback. The schema.org `Article.image` uses the hero when present.

## Prerequisites

1. **Apply the migration first.** Adds the three columns. It is NOT applied
   automatically — run it via the Supabase dashboard SQL editor (or MCP
   `apply_migration`):

   ```
   apps/hub/supabase/migrations/20260607_gap_page_visuals.sql
   ```

2. **Node 22+** (uses built-in `fetch`). No `npm install` needed — the
   script talks to Supabase REST/Storage, OpenAI, and Anthropic over HTTP
   directly.

## Running

**Dry-run (default — no writes, no API spend):**

```powershell
node scripts/generate-gap-visuals.mjs
```

**Generate + write for ALL pages missing a hero (this is the full run):**

```powershell
node scripts/generate-gap-visuals.mjs --apply
```

**Useful flags:**

```powershell
node scripts/generate-gap-visuals.mjs --apply --limit 1            # smoke test one row
node scripts/generate-gap-visuals.mjs --apply --slug fincen-boi-gap
node scripts/generate-gap-visuals.mjs --apply --quality low        # ~4x cheaper images
node scripts/generate-gap-visuals.mjs --apply --skip-diagram       # hero only
node scripts/generate-gap-visuals.mjs --apply --skip-hero          # diagram only
node scripts/generate-gap-visuals.mjs --help
```

The script is **idempotent**: rows that already have `hero_image_url` are
skipped; diagrams are generated only when missing. Re-running after a partial
failure is safe.

| Hero image (medium, default) | gpt-image-1, 1536x1024 | ~$0.06 (range $0.04–0.17) |

Rough totals for ~50 gap pages: **~$3.00–3.50** at medium quality, **~$1**
at low quality. Always dry-run first to confirm the row count, then start
with `--limit 1` to eyeball one result before the full run.

## Troubleshooting

### `FATAL: fetch failed` / `UNABLE_TO_VERIFY_LEAF_SIGNATURE`

This machine has a TLS-interception proxy whose CA is trusted by Windows
(so PowerShell `Invoke-WebRequest` works) but **not** by Node's bundled CA
store, so Node's `fetch` rejects the leaf certificate. Two fixes:

```powershell
# Point Node at the corporate/interception CA bundle (preferred):
$env:NODE_EXTRA_CA_CERTS = "C:\path\to\corporate-root-ca.pem"
node scripts/generate-gap-visuals.mjs --apply

# OR run from a network without TLS interception (e.g. the deploy host).
```

Last-resort only (insecure, do NOT use on shared networks):
`$env:NODE_TLS_REJECT_UNAUTHORIZED = "0"`.

### `401 Unauthorized` from OpenAI or Supabase

The key in the vault is invalid/revoked or lacks access. Confirm the
current `OPENAI_API_KEY` and `SUPABASE_SERVICE_KEY` values, and that the
Supabase project accepts the key format you're using (legacy JWT
service-role vs. new `sb_secret_…`). The script auto-detects the key format
for header construction.

## Notes

- Images are stored as `<slug>.png` in the public `gap-visuals` bucket;
  re-running overwrites (upsert) rather than duplicating.
- The Mermaid prompt asks for a `flowchart TD` with 6–12 nodes; the script
  validates the output starts with `flowchart`/`graph` before writing.
- Rate-limited via `--delay` (default 1500ms between rows).
