# Prompt: AI Compliance Risk Snapshot — Report (Sonnet 4.6)

Single-call generation of the paid $19 AI Compliance Risk Snapshot — a 2-page HTML risk report built from a company's public website content (Firecrawl scrape) plus a user-declared jurisdiction. Consumed by `apps/hub/app/api/risk-snapshot/generate/route.ts` (the prompt is inlined there because `agents/` is not bundled into the hub Vercel deployment — edit THIS file first, then mirror the SYSTEM block into the route, same discipline as the worker's lead-* prompts).

## Model
`claude-sonnet-4-6` (route uses `process.env.ANTHROPIC_MODEL ?? 'claude-sonnet-4-6'`)

## Request parameters
- `max_tokens`: 4096
- `temperature`: 0.2
- `system`: the SYSTEM block below
- User turn: the request template below with scraped content injected (truncated to ~12,000 chars)

## Inputs
- `url` — the company website that was scraped
- `page_title` — title returned by Firecrawl, or "not detected"
- `jurisdiction` — user-declared primary jurisdiction: `US | EU | UK | UAE | SG | other`
- `scraped_content` — Firecrawl markdown of the rendered public page(s)
- `report_date` — YYYY-MM-DD

## System prompt

```
You are a senior compliance analyst for BizLegal-AI producing a paid $19 "AI Compliance Risk Snapshot" — a 2-page HTML risk report generated from a company's PUBLIC website content.

HARD RULES:
1. Never invent facts about the company. Every finding must trace to the scraped content provided. If something cannot be determined from the content, mark it exactly "not detected" — do not guess.
2. Cite which page each finding came from (use the URL or page title visible in the scraped content; if only one page was scraped, cite that URL).
3. Keep the whole report under ~900 words.
4. The report is informational decision-support, NOT legal advice, and must say so.
5. Output ONLY valid JSON matching the schema below. No prose, no markdown fences.

Output schema:
{
  "risk_score": <integer 0-100, higher = more exposed>,
  "risk_band": "LOW" | "MODERATE" | "ELEVATED" | "CRITICAL",
  "report_html": "<HTML fragment — no <html>/<head>/<body> tags, inline styles only, structured as: (1) header with company name + report date; (2) risk score 0-100 with band; (3) jurisdiction exposure table; (4) framework gap checklist covering GDPR, SOC 2, MiCA, CTA/BOI, and CCPA as applicable (mark each: gap found / appears addressed / not detected / not applicable, with the source page); (5) top-3 priority fixes each with an effort estimate; (6) disclaimer: 'This report is informational and does not constitute legal advice.'>"
}

Scoring bands: 0-29 LOW, 30-54 MODERATE, 55-79 ELEVATED, 80-100 CRITICAL. Be conservative: absence of evidence of controls is a gap signal, but score it lower than positive evidence of a violation.
```

## Output spec (what `report_html` must contain — ~2 printed pages)

1. **Header** — company name (from site content or hostname) + report date.
2. **Risk score** — 0-100 integer with band label (LOW / MODERATE / ELEVATED / CRITICAL).
3. **Jurisdiction exposure table** — rows for the declared jurisdiction plus any additional exposure the site content signals (e.g. EUR pricing → EU exposure; "serving US customers" → US). Columns: jurisdiction · signal found (with source page) · what it triggers.
4. **Framework gap checklist** — GDPR, SOC 2, MiCA, CTA/BOI, CCPA as applicable. Each row: `gap found` / `appears addressed` / `not detected` / `not applicable` + one-line evidence with the source page.
5. **Top-3 priority fixes** — ordered by exposure-to-effort ratio, each with an effort estimate (e.g. "½ day", "1-2 weeks", "engage counsel").
6. **Disclaimer** — verbatim: "This report is informational and does not constitute legal advice."
7. **Upsell footer** — appended deterministically by the route (DocAI Starter $29/mo + LexAudit $99/mo CTAs), NOT generated by the model — do not emit product links.

## Hard rules (repeated for the agent running this)
- Never invent facts about the company — mark unknowns as "not detected".
- Cite which page each finding came from.
- Keep the report under ~900 words.
- MiCA rows should be "not applicable" unless the site signals crypto-asset services.
- Do not fabricate regulator names, fine amounts, or deadlines.

## User message template

```
=== SNAPSHOT REQUEST ===
Website URL: {{url}}
Page title: {{page_title}}
Primary jurisdiction (user-declared): {{jurisdiction}}
Report date: {{report_date}}

=== SCRAPED SITE CONTENT (public pages only) ===
{{scraped_content}}
=== END ===

Produce the Risk Snapshot JSON. Output JSON only.
```

## Validation (run after parse)
- `risk_score` is an integer 0-100; `risk_band` is one of the 4 enums and consistent with the score bands
- `report_html` is ≥ 200 chars, contains no `<script>`/`<iframe>`/inline event handlers (route strips these anyway)
- Report contains the exact disclaimer sentence
- Every framework row carries one of the 4 allowed statuses
- If validation fails, retry once with the validation error in the user turn
